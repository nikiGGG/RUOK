**Issue 1 (blocker — anti-pattern #4, FR coverage)**: `FR-001` is in `requirement_refs` but its config-validation behavior has no test assertion. `loadConfig()` in `src/lib/db/index.ts` implements FR-001 (DATABASE_TYPE defaults to `sqlite`; only `sqlite`/`postgres` accepted; `postgres` requires `DATABASE_URL`; never fallback), but every test calls `createDatabaseServices` directly with an explicit config object (`tests/db/fixtures.ts:163,204`) and none exercise `loadConfig`. Add a unit test (e.g. `tests/db/config.test.ts`) asserting: (a) omitted `DATABASE_TYPE` → `sqlite` with default `data/okr.db` path; (b) `DATABASE_TYPE=postgres` without `DATABASE_URL` → throws; (c) invalid type → throws; (d) bounded `DATABASE_POOL_MAX`/`DATABASE_CONNECT_TIMEOUT_MS` accepted and invalid values rejected (also helps FR-009). Otherwise FR-001 is covered only by code, not by a test that would fail if the implementation changed.
